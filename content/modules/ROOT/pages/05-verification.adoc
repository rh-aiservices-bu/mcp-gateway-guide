= Phase 5: Verification

Verify end-to-end MCP session initialization and tool discovery through the {mcp-gw}.

TIP: All file paths and `oc apply` commands in this guide are relative to the link:{repo-url}[mcp-gateway-guide] repository root.

IMPORTANT: This guide is not a replacement for the link:https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.4/html/install_the_mcp_gateway/mcp-gateway-install[official {rhcl} {mcp-gw} documentation].

== Overview

The MCP protocol uses a JSON-RPC session-based flow. To verify the gateway is working:

1. *Initialize* an MCP session and capture the session ID from response headers
2. *List tools* using the session ID to discover all aggregated tools
3. *Call a tool* to verify end-to-end connectivity

== Verification Steps

=== Step 1: Get the MCP Gateway Endpoint

[source,bash]
----
export MCP_HOSTNAME="mcp.$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')"
export MCP_URL="https://${MCP_HOSTNAME}/mcp"
echo "MCP endpoint: $MCP_URL"
----

=== Step 2: Initialize MCP Session

Send an `initialize` request and capture the session ID from response headers:

[source,bash]
----
curl -sk -D /tmp/mcp_headers -X POST "${MCP_URL}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "initialize",
    "params": {
      "protocolVersion": "2025-06-18",
      "capabilities": {},
      "clientInfo": {
        "name": "test-client",
        "version": "1.0.0"
      }
    }
  }'
----

You should see a JSON response with the server capabilities:

[source,json]
----
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "protocolVersion": "2025-06-18",
    "capabilities": {
      "tools": { "listChanged": true }
    },
    "serverInfo": {
      "name": "Kuadrant MCP Gateway",
      "version": "0.0.1"
    }
  }
}
----

=== Step 3: Capture Session ID

Extract the MCP session ID from the response headers:

[source,bash]
----
SESSION_ID=$(grep -i "mcp-session-id:" /tmp/mcp_headers | cut -d' ' -f2 | tr -d '\r')
echo "MCP Session ID: $SESSION_ID"
----

=== Step 4: List Available Tools

Use the session ID to list all tools aggregated by the gateway:

[source,bash]
----
curl -sk -X POST "${MCP_URL}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: ${SESSION_ID}" \
  -d '{"jsonrpc": "2.0", "id": 2, "method": "tools/list"}' | jq '.result.tools[].name'
----

You should see tools from both registered servers with their prefixes, plus gateway-level tools (13 total):

[source]
----
"discover_tools"
"risk_assess_asset_sufficiency"
"risk_assess_income_stability"
"risk_calculate_dti"
"risk_calculate_ltv"
"risk_evaluate_credit_risk"
"risk_generate_risk_recommendation"
"select_tools"
"test1_add_tool"
"test1_greet"
"test1_headers"
"test1_slow"
"test1_time"
----

=== Step 5: Test a Tool Call

Call the risk server's DTI calculation tool with sample mortgage data:

[source,bash]
----
curl -sk -X POST "${MCP_URL}" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -H "mcp-session-id: ${SESSION_ID}" \
  -d '{
    "jsonrpc": "2.0",
    "id": 3,
    "method": "tools/call",
    "params": {
      "name": "risk_calculate_dti",
      "arguments": {
        "monthly_income": 8000,
        "monthly_debts": 2400
      }
    }
  }' | grep '^data: ' | sed 's/^data: //' | jq '.'
----

NOTE: The `tools/call` response uses Server-Sent Events (SSE) format with `content-type: text/event-stream`. The JSON payload is in the `data:` field, so you need to extract it with `grep '^data: '` before piping to `jq`.

Expected response with DTI calculation:

[source,json]
----
{
  "jsonrpc": "2.0",
  "id": 3,
  "result": {
    "content": [
      {
        "type": "text",
        "text": "{\"value\": 30.0, \"rating\": \"Low\", \"guidance\": \"Well within conventional guidelines\"}"
      }
    ]
  }
}
----

=== Step 6: Clean Up Headers File

[source,bash]
----
rm -f /tmp/mcp_headers
----

== Using the Verify Script

You can run all verification steps automatically:

[source,bash]
----
./scripts/verify.sh
----

The script performs the full MCP session flow and validates tool discovery.

== Using MCP Inspector (Optional)

If you have Node.js installed, you can use the official MCP Inspector for interactive testing:

[source,bash]
----
npx @modelcontextprotocol/inspector@latest
----

Then connect to `https://\{MCP_HOSTNAME}/mcp` using the Streamable HTTP transport.

== Troubleshooting

=== No Tools Returned

* Check that MCPServerRegistrations are Ready: `oc get mcpsr -A`
* Check broker logs: `oc logs -n mcp-gateway deployment/mcp-gateway --tail=30`
* Verify the MCP servers are running: `oc get pods -n mcp-test`

=== Connection Refused

* Verify the Gateway is Programmed: `oc get gateway -n mcp-gateway`
* Check the Route exists: `oc get routes -n mcp-gateway`
* Verify DNS resolves: `nslookup \{MCP_HOSTNAME}`

=== Session ID Not Found

* Make sure you are using `-D` flag to dump headers
* Check the response for errors in the initialize call
