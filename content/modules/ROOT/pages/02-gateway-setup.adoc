= Phase 2: Gateway Setup

Create a Kubernetes Gateway object with an MCP listener for the {mcp-gw}.

TIP: All file paths and `oc apply` commands in this guide are relative to the link:{repo-url}[mcp-gateway-guide] repository root.

IMPORTANT: This guide is not a replacement for the link:https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.4/html/install_the_mcp_gateway/mcp-gateway-install[official {rhcl} {mcp-gw} documentation].

== Overview

The {mcp-gw} uses the Kubernetes Gateway API to expose MCP endpoints. The `istio` GatewayClass, provided by OpenShift Service Mesh 3 (OSSM3), handles Gateway API support for the MCP Gateway.

The Gateway needs at least two listeners:

* An `mcp` listener for external MCP protocol traffic
* An `mcps` listener for internal backend routing to MCP servers

The `mcps` listener uses a wildcard hostname (`*.mcp.local`) on port 8080 with HTTP protocol. This wildcard pattern simplifies backend routing - each MCP server gets a unique hostname (e.g., `test-server1.mcp.local`, `risk-server.mcp.local`) without requiring DNS configuration, since the traffic stays internal to the cluster.

== Installation

=== Step 1: Determine Your Cluster Domain

The Gateway hostname is based on your cluster's application domain:

[source,bash]
----
export CLUSTER_DOMAIN=$(oc get ingresses.config.openshift.io cluster -o jsonpath='{.spec.domain}')
echo "Cluster domain: $CLUSTER_DOMAIN"
----

=== Step 2: Create the Gateway

Generate the Gateway manifest with your cluster domain and apply it:

[source,bash]
----
export MCP_HOSTNAME="mcp.${CLUSTER_DOMAIN}"
echo "MCP hostname: $MCP_HOSTNAME"

envsubst < manifests/02-gateway-setup/gateway.yaml.tmpl | oc apply -f -
----

This creates a Gateway in the `mcp-gateway` namespace with:

* *mcp listener* (port 8080) - Main MCP protocol endpoint for external traffic
* *mcps listener* (port 8080, hostname: `*.mcp.local`) - Internal listener for MCP server backend routing
* Hostname set to `mcp.<cluster-domain>` for the external listener
* `gatewayClassName: istio`

NOTE: With the `istio` GatewayClass, the gateway proxy (Envoy) deploys in the `mcp-gateway` namespace as `mcp-gateway-istio`. Both the Gateway object and the proxy deployment live in the same namespace.

=== Step 3: Create the OpenShift Route

The `istio` GatewayClass creates a LoadBalancer service, but on bare-metal or workshop clusters without MetalLB, external access requires an OpenShift Route:

[source,bash]
----
envsubst < manifests/02-gateway-setup/route.yaml.tmpl | oc apply -f -
----

This creates an edge-TLS Route that bridges external traffic from the default HAProxy ingress controller to the gateway service on port 8080.

== Verification

=== Wait for Gateway to be Accepted

[source,bash]
----
oc wait gateway/mcp-gateway -n mcp-gateway \
  --for=condition=Accepted --timeout=120s
----

NOTE: The top-level `Programmed` condition may show `False` with `AddressNotAssigned` because the `istio` GatewayClass creates a LoadBalancer service that stays `<pending>` without MetalLB. This is expected - the OpenShift Route bypasses the LoadBalancer. Check the individual listener conditions instead, which should show `Programmed: True`.

=== Check Gateway Proxy Pod

[source,bash]
----
oc get pods -n mcp-gateway -l gateway.networking.k8s.io/gateway-name=mcp-gateway
----

The gateway proxy pod (`mcp-gateway-istio-*`) should be `Running` and `Ready`.

=== Verify the Route is Created

Check the Route was created in the `mcp-gateway` namespace:

[source,bash]
----
oc get routes -n mcp-gateway
----

== DNS Management

The OpenShift Route uses the cluster's wildcard DNS (`*.apps.<cluster-domain>`), so no additional DNS configuration is needed. The Route bridges external traffic through the default HAProxy ingress controller to the gateway service.

On cloud platforms ({ocp-short} on AWS, Azure, GCP), you could alternatively use MetalLB or cloud LoadBalancer for direct access to the `istio` gateway service. See the link:https://docs.redhat.com/en/documentation/red_hat_connectivity_link/1.4/html/install_the_mcp_gateway/mcp-gateway-install#dns-management_mcp-gateway-install[DNS Management] section in the official documentation.
